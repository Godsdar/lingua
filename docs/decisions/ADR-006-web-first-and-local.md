# ADR-006: Веб первым, локальное хранение, без ежедневного пазла (пока)

## Status
Accepted

## Date
2026-10-01

## Context
Нужно определить первую поверхность для финальной сборки, способ хранения и
наличие геймификации. Бюджета нет; цель — минимальный барьер входа и встроенная
виральность (см. `POSITIONING.md`).

## Decision
1. **Первая поверхность — веб-приложение** (тот же renderer, ядро работает в
   браузере; сервер не нужен благодаря CORS Wiktionary `origin=*` и MyMemory).
   Десктоп и расширение остаются, но не блокируют релиз.
2. **Шаринг входит в MVP:** генерация картинки-карточки древа (canvas) +
   копирование пермалинка (query-параметры). Это виральный артефакт.
3. **Хранение — локальное, без аккаунта:** коллекция «Мои корни» и счётчик
   находок в `localStorage`; синхронизация и SRS — позже.
4. **Ежедневный пазл / «корень дня» — отложить.** Не строим сейчас, чтобы не
   дрейфовать в игру; вернёмся после проверки спроса на ядро.

## Alternatives Considered
- **Расширение первым** — сильный повтор, но выше порог установки и меньше SEO.
- **Десктоп первым** — трение установки и платная подпись (см. ADR-005).
- **Аккаунт + синк сразу** — бэкенд, приватность, отсрочка релиза.
- **Root Path сразу** — рост, но риск смещения продукта в игру до его проверки.

## Consequences
- Плюс: бесплатный запуск (`build:web` → любой статик-хостинг), SEO-страницы.
- Плюс: ничего не хранится на сервере — сильное обещание приватности.
- Минус: прогресс не переносится между устройствами до появления синка.
- Триггер для пересмотра: если retention на вебе слабый — вернуть «корень дня»
  и/или синк.
